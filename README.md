# xiaolin-article · 小霖 AI 产品文章写作 Skill

> 把零散的产品观察、项目经验和公开资料，整理成有明确观点、有事实依据、能改变读者产品判断的中文文章。

**xiaolin-article** 是一个面向 AI 编码代理（pi、Codex、OpenAI Agents 等）的个人写作 Skill，承载作者小霖长期稳定的写作方法与作者位置。它把「写 AI 产品文章」这件事拆成一段可复用的协作流程：先讨论文章要说什么，再确认怎样展开，随后按章节写作并合稿审校。

面向 **AI 产品经理** 方向的专业内容写作，覆盖公众号、人人都是产品经理、少数派等平台的新写、重写和改稿。

- 版本：`3.7.0`
- 许可证：[MIT](./LICENSE)

---

## 它解决什么问题

- **素材零散** → 先把材料建立关系，再形成观点和结构，而不是堆信息。
- **资料很多** → 找出哪些材料真正改变结论，避免写成信息汇编。
- **专业内容生硬** → 用产品场景、真实流程和决策问题解释，同时保留必要的技术精度。

核心是把零散素材转化为 **「事实 — 机制 — 产品判断 — 验证顺序」** 的完整论证，而不是一份功能清单或资料汇编。

---

## 写作范围

只处理 AI 产品经理方向的专业内容：

- AI 行业观察与观点评论
- AI 产品分析、竞品拆解和体验评测
- AI 产品项目复盘、工作方法和职业思考
- 大模型、Agent、RAG、评测、多模态等面向产品经理的技术科普

小说、诗歌、泛生活随笔、纯文学创作、普通营销软文和学术论文不属于本 Skill。医疗 AI 可以写，但文章仍要落到产品问题、使用场景、技术选择或行业判断。

## 工作流程

默认把写作当成一段协作过程，除非用户明确要求一次完成，否则不会收到题目后直接交出整篇长文。

1. **整理任务和材料** — 判断新写 / 重写 / 扩写 / 改稿，确认主题、读者、平台、篇幅与已有材料，并把材料分成五类（亲历、官方资料、可靠数据、既有判断、未确认部分）。
2. **讨论观点** — 交付一份简洁的观点讨论稿：真正要回答的问题、推荐的核心观点、支撑判断、最有力的反方、证据能支持到哪里。
3. **确认大纲和章节逻辑** — 给出四到七个主体章节，写清每章「接住什么、解决什么、用什么材料、得出什么判断、为什么带到下一节」，并用问题链串联全文。
4. **按章节生成** — 每轮完成一个完整章节，用事实、案例和机制托住判断。
5. **合稿与审校** — 合并全文，统一术语与数字口径，删除重复，核对标题、开头、结尾与证据的一致性，并运行检查脚本。

## 作者风格特征

成稿优先呈现已经形成的稳定写法：

- **从小细节进入大问题** — 先到具体现场，再追问细节说明了什么产品机制。
- **批评锋利，但不急着判死刑** — 区分愿景是否成立、需求是否存在、当前路径是否跑通、验证顺序是否合理。
- **把矛盾压缩成可复用概念** — 例如「双重冷启动」「价值出现得太晚」，但先让事实和流程成立再命名。
- **建议是验证顺序，不是功能清单** — 优先回答最先服务谁、先证明什么、价值何时出现。
- **结尾保留人本尺度** — 由全文论证自然抵达，不突然谈「时代浪潮」。
- **克制、公平、有反方意识** — 核验时效事实，不虚构经历，不擅自公开作者的私人爱好、脆弱感或可能影响职业形象的信息。

## 安装与使用

### pi

将整个目录放入 pi 的全局技能目录：

```bash
git clone https://github.com/cpp285/xiaolin-article-skill.git ~/.agents/skills/xiaolin-article-skill
```

重启 pi 后，它会自动发现 `SKILL.md`。当任务涉及 AI 产品文章写作时，可用 `/skill:xiaolin-article` 显式加载。

### Codex / OpenAI Agents

`agents/openai.yaml` 提供对应的代理配置（含显示名、简短描述与默认提示词），可按你的代理工具链引用。

## 检查脚本

长稿保存为 Markdown 或文本后，可运行风格检查脚本：

```bash
python3 scripts/check_prose.py <稿件路径>
# 或从标准输入读取
cat 稿件.md | python3 scripts/check_prose.py -
```

脚本会检查过度口语与网络梗、标题夸大、对照句式、商业黑话、名词化表达、连词密度、段落节奏、数据密集但缺少解释等「可疑语言形状」。除硬性项外，其余提示都需结合上下文人工判断。
